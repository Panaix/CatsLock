## Сообщения об ошибках и предложения

Перед созданием Issue проверьте, не сообщал ли кто-то уже о той же проблеме.
Используйте шаблоны Issues и указывайте версию PurrLock, версию macOS,
архитектуру компьютера и минимальные шаги для воспроизведения.

Не добавляйте в отчёты пароли, личные данные или содержимое клавиатурного ввода.
Для сообщений об уязвимостях следуйте инструкциям в [SECURITY.md](SECURITY.md),
а не открывайте публичный Issue.

## Изменения кода

1. Создайте ветку от `main`.
2. Внесите небольшое, сфокусированное изменение и обновите документацию, если
   меняется поведение приложения.
3. Проверьте изменения локально:

   ```sh
   swiftc -typecheck main.swift
   ./scripts/build-release.sh
   ```

4. Откройте pull request с описанием проблемы, решения и способа проверки.

Pull request должен проходить GitHub Actions и получать одобрение сопровождающего
перед слиянием. Не добавляйте собранные приложения, DMG-файлы, секреты или
резервные копии исходников.

## Релизы

Сопровождающий публикует тег версии вида `vX.Y.Z`. GitHub Actions собирает
Universal Binary и прикрепляет `PurrLock-Installer.dmg` к GitHub Release.
